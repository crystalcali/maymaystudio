# MayMay Studio 3

Личная веб-студия фото, видео и LoRA. Веб-приложение постоянно работает в Timeweb App Platform; GPU-агенты выполняют задания на YouGPU. Основной персонаж — May, другие персонажи независимы.

**Статус: первая инженерная сборка 3.0.0, до GPU-приёмки.** Это работающий сервер и интерфейс, а не статический макет. Обучение/генерация реализованы как вызовы закреплённого Musubi и Diffusers, но в этой среде нет CUDA и аккаунтов провайдеров. Не выдаём CPU-тесты за подтверждение качества LoRA.

## Быстрый старт локально

Нужны Python 3.12, Node.js 24 и Git. FFmpeg нужен для проверки нарезки видео.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-web.lock
npm --prefix frontend ci
npm --prefix frontend run build
python -m uvicorn maymay.api:create_app --factory --host 127.0.0.1 --port 8000
```

Откройте http://localhost:8000, пароль `maymay-local`. SQLite и файлы сохраняются локально. Для доступа с другого устройства задайте `PUBLIC_URL` заранее. Локальный пароль и SQLite не допускаются в production.

Альтернатива с Docker и локальной PostgreSQL: `docker compose up --build`. Это режим разработки; для Timeweb используйте внешние PostgreSQL и S3.

## Развёртывание

**Полная пошаговая инструкция: [docs/DEPLOY_RU.md](docs/DEPLOY_RU.md).**

1. Поместите содержимое репозитория в свой GitHub-репозиторий.
2. Создайте PostgreSQL и приватный S3 bucket.
3. Разверните Dockerfile в Timeweb App Platform, добавьте переменные из `.env.example`.
4. Соберите `Dockerfile.gpu` workflow `Build GPU agent`, сделайте образ доступным для чтения YouGPU и задайте `AGENT_IMAGE` на Timeweb.
5. Войдите в студию, добавьте YouGPU/HF токены, проверьте компоненты, выберите GPU и запустите небольшую задачу.

## Возможности

- Мобильный интерфейс: студия, персонажи, эталоны, датасеты, галерея, профили, LoRA, мощности, задачи, FAQ.
- Персонажи с собственными триггерами; отдельные FACE/BODY референсы.
- Krea RAW train / Turbo generate; Klein Base9B train / generate / reference edit.
- Wan2.2 A14B I2V/T2V train и generate, раздельные high/low LoRA; 5B generate.
- Профили с проверкой HF-доступа и фиксацией ревизий; пользовательские пути на GPU.
- Загрузка внешних LoRA файлом, прямой HF/Civitai download URL или путём на агенте.
- ZIP/фото/видео импорт, точные дубликаты, кандидаты близких изображений, captions, ручной отбор и группы исходников.
- Подготовка фото и выборочных кадров видео через Qwen2.5-VL; нарезка FFmpeg со сменами сцен и overlap.
- Неизменяемый ZIP snapshot с manifest; групповой train/validation split.
- Исходящие HTTPS-агенты, очередь с lease и attempt fencing; отмена, повтор, сверка потерянных задач.
- Галерея только медиа; LoRA и state отдельно. Экспорт LoRA и загрузка полного состояния для resume.
- Подбор предложений YouGPU, создание/сверка/terminate инстанса из UI, почасовые цены, оценки по накопленным замерам.
- Внешние PostgreSQL/S3; приватные объекты, подписанные ссылки и multipart для крупных результатов.

## Что ещё не подтверждено или не включено

- Реальная аренда/контракт YouGPU, Docker-сборки, PostgreSQL/S3 и все CUDA-рецепты требуют приёмки на вашем окружении. Для них нет отметки «проверено на GPU».
- Скорости GPU не выдуманы. До сопоставимого замера UI показывает «Скорость пока не измерена». Каталог сортируется по цене/памяти; автоматические «самый быстрый/сбалансированный» рекомендации требуют базы замеров и отдельной доводки.
- Одна GPU на задачу; несколько агентов могут выполнять независимые задачи. DDP/tensor parallel, warm model serving и multi-user SaaS не включены.
- Wan5B LoRA training и импорт 5B LoRA, Klein distilled-перенос и ускоряющие LoRA расписания не включены до GPU-проверки.
- Krea preview во время обучения — RAW с CFG. Turbo проверяется отдельной задачей после сохранения адаптера. Loss не измеряет сходство личности.
- Captioner описывает видео по 8 выборочным кадрам. Это не покадровая проверка всего движения и не доказательство идентичности. Аннотации/видимость требуют ручного подтверждения.
- Доступность внешнего адаптера окончательно проверяется на агенте при скачивании. Поддерживаются Musubi-compatible ключи LoRA; PEFT/другие форматы требуют явного преобразования. Страницы Civitai с описанием модели не являются download URL.
- При аварии агента/сети задача не перезапускается автоматически. Политика авто-terminate применяется только к созданным студией инстансам с подключённым агентом, без незавершённых задач. Сбой до регистрации агента проверяйте в YouGPU вручную.
- Почасовой расход в UI — оценка; фактический биллинг провайдера, диски и трафик учитываются отдельно. Бюджет запускает отмену, но не гарантирует отсутствие перерасхода во время завершения/сохранения.
- Нет готового полного датасета May или весов моделей в архиве. Включён один исходный портрет для интерфейса. Импортируйте свой ZIP с отобранными кадрами и captions.

## Проверки

```bash
pip install pytest
python -m pytest -q
npm --prefix frontend run build
```

CPU integration test использует реальный FFmpeg и HTTP-сервер, без аренды GPU. Браузерная визуальная QA в текущем окружении заблокирована изоляцией preview Python; перед production проверьте мобильный браузер по checklist в `docs/ACCEPTANCE.md`.

## Структура

- `maymay/` — FastAPI, хранение, очередь, рецепты и YouGPU adapter.
- `agent/` — изолированное выполнение GPU jobs и подготовка данных.
- `frontend/` — React/Vite; production bundle обслуживает FastAPI из того же домена.
- `Dockerfile`, `Dockerfile.gpu` — раздельные web/GPU образы.
- `docs/` — развёртывание, инструкции по моделям, архитектура и приёмка.
- `tests/` — контрактные, API и CPU integration проверки.

React/Vite выбран вместо отдельного Next.js-сервиса, чтобы первый деплой имел один web-контейнер, один домен и один набор cookies. PostgreSQL и S3 остаются внешними. GPU-библиотеки не устанавливаются на web-сервер.
