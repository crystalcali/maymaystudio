# Timeweb / YouGPU: настройка и проверка

## Конфигурация

Timeweb App Platform: Dockerfile в корне (проект уже перенесён из вложенной папки в main), порт 8000, health /healthz, одна реплика/один worker Uvicorn. Используйте HTTPS PUBLIC_URL фактической студии, без завершающего слеша; постоянный SECRET_KEY; ADMIN_PASSWORD; внешнюю DATABASE_URL PostgreSQL+psycopg с TLS; приватный S3_BUCKET/S3_ENDPOINT_URL/S3_REGION/AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY. Полный список — DEPLOY_RU.md.

AGENT_IMAGE — обязательный полный публично доступный образ `ghcr.io/crystalcali/maymaystudio-gpu:COMMIT_SHA` после успешного GitHub Actions Build GPU agent. Сам workflow автоматически не запускался. Не используйте случайный Ubuntu/Jupyter образ вместо агента. Dockerfile.gpu использует CUDA 12.8.1, согласованные Torch/Torchvision, pinned Musubi, pip check и import smoke; успешная сборка ещё не означает GPU-приёмку.

YouGPU API key задаётся в «Настройки» либо YOUGPU_API_KEY. Не передавайте его агенту. HF_TOKEN должен иметь read и принятые условия выбранной модели. Перед арендой проверьте модель в «Модели и LoRA»: компоненты и SHA ревизий. Для собственных абсолютных путей существование проверяется только агентом; backend не имеет доступа к его файловой системе.

Web нужен исходящий HTTPS на api.yougpu.ru. Агенту нужны исходящий HTTPS на PUBLIC_URL Studio, Hugging Face и S3. Обратные входящие порты GPU для связи со Studio не нужны. Ошибки connect от Timeweb проверяются именно с Timeweb, не только в браузере/с ноутбука. Не увеличивайте число POST retry.

## Цикл без ручного терминала

1. В «Модели и LoRA» выберите профиль, «Проверить доступ». Загрузите датасет, captions, отберите кадры и экспортируйте snapshot.
2. «Мощности» → обновить каталог и баланс. Проверьте наличие, цену, VRAM каждой карты, RAM и рабочий диск; несколько карт не складывают VRAM для одной задачи этой версии.
3. Арендуйте один инстанс с проверенным образом. Студия автоматически передаёт STUDIO_URL, одноразовый PAIRING_CODE и WORKER_NAME. Docker CMD запускает agent.main, тот регистрируется, сохраняет локальные credentials и посылает heartbeat.
4. «Сверить статус» получает состояние провайдера. ACTIVE означает готовность инстанса, **не готовность агента**. Дождитесь online heartbeat. Если агент не появился: проверьте в панели YouGPU запуск контейнера, образ, его логи и исходящую сеть; каталог тут ничего не доказывает.
5. Для реальной приёмки, **только после отдельного разрешения на оплату**, выберите BF16-совместимую GPU с достаточным диском/RAM/VRAM, одну минимальную генерацию (count=1) и явно назначьте готовый агент. Уменьшение числа шагов не доказывает возможность загрузить большую модель.
6. Проверьте стадии скачивания/подготовки/вычисления и появление файла в галерее; скачайте файл и проверьте S3. Повторите с одной совместимой LoRA. Затем короткая тренировка с промежуточным сохранением и проверкой resume.
7. Проверьте отмену во время работы: SIGINT, затем принудительная остановка по таймауту; дождитесь terminal и загрузки готовых файлов. Инстанс продолжает оплачиваться.
8. Нажмите «Завершить аренду», затем «Сверить статус» до TERMINATED. Подтвердите отсутствие активной аренды и правильный биллинг в YouGPU; STOPPED не заменяет terminate. Хранилища могут оплачиваться отдельно.

Автотесты ничего не арендуют. Реальная приёмка шагов 5–8 в этом обновлении не проводилась.

## Неопределённый результат

При timeout/502 создания не нажимайте новую аренду с новым request_id. В уже созданной карточке нажмите «Сверить статус»: поиск /instances по полному уникальному имени, затем получение /instances/{id}. Ни одного повторного create. Если совпадений 0 или несколько, Studio сохраняет неопределённость — проверьте имя/ID в YouGPU, повторите сверку позднее. Не выбирайте случайный инстанс.
Если сеть пропала после принятия одноразовой регистрации, код мог быть использован. Автоматический повтор после ReadTimeout намеренно запрещён; проверьте логи и подключение существующего инстанса. Полностью автоматическая удалённая переустановка/перезапуск агента через SSH не реализованы.

Проверка баланса независима от каталога. При 401/403 проверьте права ключа; не заменяйте ошибку нулём. Цена сессии в Studio — оценка, API balance показывает фактический общий hourly_rate и pending.

## Официальные контракты (сверено 28.10.2026)

- https://docs.yougpu.ru/api/overview/ — base https://api.yougpu.ru
- https://docs.yougpu.ru/api/instances/create/ — POST /instances, X-API-KEY, instance_name/offer_id/image_id/ssh_keys/docker_config
- https://docs.yougpu.ru/api/instances/list/ — GET /instances, data array
- https://docs.yougpu.ru/api/catalog/offers/ — price, in_stock, region, available_images
- https://docs.yougpu.ru/api/billing/balance/ — GET /billing/balance, available/hourly_rate/pending/total

API развивается. Сохранённый контрактный тест — защита от известных регрессий, не гарантия неизменности сервиса.

## Исправление по фактическому ответу API и скриншотам

28.10.2026 публичные GET подтвердили: некоторые offer не содержат in_stock, а GPU stats содержит in_stock_count. Отсутствие поля не означает false. Если вся группа доступна (in_stock_count == total_offers > 0), наличие можно вывести из сводки; для смешанной/неизвестной группы показывается «наличие неизвестно», аренда остаётся заблокированной. Это вывод из API, не проверка успешной аренды. Семейства с наличием запрашиваются первыми; частичный каталог показывает список не проверенных семейств и сохраняет отметку в кэше.

Для старой записи без provider_id сумма расхода неизвестна; часы с момента записи не выдаются за фактический счёт. «Завершить аренду» сначала выполняет read-only сверку ID, затем один запрос terminate. «Убрать запись» требует подтверждения и успешной проверки отсутствия инстанса с точным именем либо его TERMINATED; при активной задаче/живом агенте действие блокируется. Архивирование не останавливает тарификацию иных/переименованных инстансов. История записи сохраняется в БД.
