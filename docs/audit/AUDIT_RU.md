## Что не доказано

502/ConnectTimeout на конкретном Timeweb не воспроизведены: доступа к его журналам и сетевой конфигурации нет. Возможны маршрут, proxy, upstream и таймаут reverse proxy. Успешный публичный каталог с другой машины не исключает их.
`reconcile_required` сам по себе — защитный статус, а не доказательство неуспешной оплаты. При неизвестном исходе создания новая аренда запрещена; нужна сверка.
AGENT_IMAGE и закреплённый профиль — обязательные условия, не ошибки, которые следует обходить.

## Новые интерфейсные возможности

Баланс из официального GET /billing/balance: available / hourly_rate / pending / total. При ошибке сумма не выдумывается. Расход отдельного узла остаётся приблизительным, фактический биллинг авторитетен.
Каталог показывает наличие, stale/partial; карточки агентов — последний heartbeat; карточки инстансов — русские состояния, подключение агента, активную стадию/прогресс/ETA и диагностику операции. Сверка и завершение аренды — разные кнопки; отмена задания не завершает аренду.
Пользовательский профиль можно создать сохранением копии, переименовать, редактировать, проверить и удалить. API дополнительно предоставляет POST /profiles/{id}/copy. Системные пресеты можно настраивать/сбрасывать, но нельзя удалить или сменить их архитектуру. Профиль, используемый историей заданий, не удаляется.
Датасеты имеют отдельные настройки материала, правил captions, разрешения, отбора и split. Caption rules передаются captioner; split применяется к snapshot и обучению. Разрешение — настройка набора для оператора, оно не переопределяет явный параметр тренера. Стратегии отбора требуют ручной проверки; поиск близких дубликатов сохранён.
История экспортов содержит SHA и revision; экспортированные версии неизменяемы. До обновления история экспортов не регистрировалась; старые ключи в заданиях остаются доступны.

## Удаление и S3

DELETE требует `?confirm=true`, UI показывает подтверждение. Активное задание с dataset_id блокирует удаление набора/его файлов. Исторические job.params и snapshot остаются неизменными.
Удаление удаляет записи редактируемого набора, **не физические байты S3**. Это намеренная консервативная политика: общие Artifact/Item, snapshot и входы подготовки не повреждаются. Автоматический GC не реализован; хранение не освобождается. Не настраивайте lifecycle для удаления исходников/snapshots по возрасту. Неизменяемый ZIP содержит байты примеров, а не ссылки на исходники.
Новые настройки и реестр snapshot используют существующую KV таблицу, без миграции схемы.
