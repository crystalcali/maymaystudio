# Приёмка перед постоянной эксплуатацией

## Выполнено в среде разработки

- Production-сборка React/Vite.
- API/контрактные CPU-тесты: вход и Origin, одноразовая регистрация, lease/attempt fencing, отмена, фильтрация галереи, checksum/идемпотентность артефактов, шифрование секретов, безопасный ZIP, дубликаты, детерминированные snapshots, группы train/validation, сохранение очереди после перезапуска.
- Полный HTTP/FFmpeg CPU-прогон агента с загрузкой видео, нарезкой и сохранением файлов в редакторе.
- Проверка зависимостей web через pip check.

## Требуется на вашем окружении

1. Dockerfile и Dockerfile.gpu собираются; doctor на GPU проверяет imports/CUDA/BF16/диск. У этого исполнителя Docker и CUDA отсутствуют.
2. Подключение к внешней PostgreSQL и S3, в том числе большой multipart state ZIP. Проверить backup/restore.
3. Реальное создание YouGPU инстанса, pairing из Docker env, источник цены/валюты, облачные статусы и terminate. API провайдера меняется; при расхождении исправляется adapter и его fixture.
4. На каждой GPU/recipe: загрузка весов, кэш, несколько шагов train, LoRA export, правильное применение, preview, state/resume, отмена и выгрузка.
5. Для Krea: RAW-training/Turbo-inference; для Klein Base: generation/edit с несколькими LoRA; для Wan: соответствующие high/low experts, T2V/I2V, 5B VAE и decode.
6. Проверить качество лица/фигуры/родинки May на фиксированных новых сценах и увеличенных полноростовых лицах. Метрики loss/сходства сами по себе не достаточны.
7. Отключить сеть worker; убедиться, что lease не создаёт дубликат, процесс прекращается, задача требует сверки.
8. Закрыть браузер и обновить web; активная GPU-задача продолжает работу, результаты читаются после terminate.
9. Проверить auto-terminate на короткой дешёвой задаче. При отказе агента/веб-сервера контролировать аренду независимо в консоли провайдера.
10. Мобильный Safari/Chrome: вход, выбор профиля, upload, клавиатура, captions, галерея/сравнение/скачивание, queue cancellation. В текущей preview-среде браузерная QA блокируется недоступными Python-зависимостями изолированного preview.

Ни один CUDA-пайплайн в этой сборке не маркируется как рекомендованный без этих прогонов. Оценки скорости/стоимости нельзя заранее заполнить вымышленными числами.
