# Развёртывание MayMay Studio 3

Текущий процесс: [ручное подключение GPU](MANUAL_GPU_RU.md). Старые отчёты об аренде отражают предыдущие этапы разработки.

## Что понадобится

- Timeweb Cloud App Platform, внешняя PostgreSQL и приватный S3 bucket.
- GitHub-репозиторий с этим кодом и реестр контейнеров GHCR.
- Аккаунт YouGPU с API key и балансом.
- HF read token с разрешениями на выбранные gated-модели; условия доступа принимаются в вашем HF аккаунте.

Ключи задавайте в Timeweb Environment Variables или в разделе «Настройки» после входа. Не добавляйте их в Git, README, URL или чат.

## 1. Загрузить репозиторий в GitHub

Создайте пустой репозиторий, распакуйте архив и загрузите **содержимое папки maymay-studio-3**, чтобы Dockerfile находился в корне репозитория. Можно использовать GitHub Desktop/VS Code или:

```bash
git init
git add .
git commit -m "MayMay Studio 3 initial implementation"
git branch -M main
git remote add origin https://github.com/YOUR_LOGIN/YOUR_REPOSITORY.git
git push -u origin main
```

`.env`, локальная база и runtime-файлы игнорируются. `.github/workflows/checks.yml` запускает тесты и сборку UI. Если у вас нет GitHub Actions, соберите Docker-образы локально на машине с Docker и отправьте в реестр вручную.

## 2. Постоянная база и S3

Создайте PostgreSQL, базу `maymay` и отдельного пользователя с правом создавать таблицы в ней. Включите TLS и разрешите подключение backend-приложения в настройках сети. Строка:

```text
postgresql+psycopg://USER:PASSWORD@HOST:5432/maymay?sslmode=require
```

Специальные символы логина/пароля должны быть percent-encoded. Начальные таблицы создаются при первом старте. Это новая схема v3; существующая база v1/v2 автоматически не мигрирует. Перед будущим изменением схемы нужна отдельная миграция и backup.

Создайте приватный S3 bucket. Выпустите ключ, ограниченный этим bucket: ListBucket, GetObject, PutObject, DeleteObject, multipart create/upload/complete/abort. Запишите точные endpoint и region из панели вашего хранилища. Значения `.env.example` — ориентир, не замена настройкам панели.

Включите версионирование объектов и lifecycle для удаления незавершённых multipart uploads. Резервируйте PostgreSQL и bucket: один без другого не восстанавливает всю студию. Для загрузки агентом по подписанным ссылкам публичный bucket не требуется.

## 3. Web-приложение в Timeweb App Platform

1. Создайте backend/container application и подключите GitHub-репозиторий, ветку `main`.
2. Выберите сборку из Dockerfile в корне; контекст — весь репозиторий. Имя `Dockerfile`, порт `8000`.
3. Начальный практический профиль web: 2 vCPU / 2–4 GB RAM, затем оцените по реальному размеру импортов. Это ориентир для control plane, GPU здесь не нужна.
4. Добавьте переменные:

| Переменная | Значение |
|---|---|
| `STUDIO_ENV` | `production` |
| `PUBLIC_URL` | Полный HTTPS-адрес студии без завершающего `/` |
| `ADMIN_PASSWORD` | Уникальный пароль от 14 символов |
| `SECRET_KEY` | Случайный постоянный секрет от 32 символов |
| `DATABASE_URL` | Строка внешней PostgreSQL |
| `S3_ENDPOINT_URL` | Endpoint вашего bucket |
| `S3_REGION` | Region из панели |
| `S3_BUCKET` | Имя bucket |
| `AWS_ACCESS_KEY_ID` | S3 access key |
| `AWS_SECRET_ACCESS_KEY` | S3 secret key |
| `PORT` | `8000` |
| `AGENT_IMAGE` | Добавляется на шаге 4 |

Создать секрет локально: `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Сохраните его в менеджере паролей. **Не меняйте SECRET_KEY при каждом redeploy:** он используется для cookies, подписей и шифрования токенов в БД.

5. Запустите деплой. Проверка готовности: `https://ВАШ_АДРЕС/healthz` должна вернуть `status: ok`.
6. Откройте студию, войдите с `ADMIN_PASSWORD`. При смене домена сначала исправьте `PUBLIC_URL` и выполните redeploy; иначе защита Origin отклонит изменения, а ссылки будут неправильными.

В production приложение откажется запускаться с SQLite, локальным хранилищем или стандартным секретом. Веб-контейнер временный; пользовательские данные в его файловую систему не записываются как единственное хранилище.

Используйте один процесс Uvicorn/одну реплику web в этой версии: начальная схема и supervisor рассчитаны на такое развёртывание. GPU-агенты независимы и могут быть несколькими. Если App Platform ограничивает длительность/размер HTTP upload, большие ZIP загружайте порциями либо измените лимиты тарифа; верхний предел приложения задаёт `MAX_UPLOAD_MB`.

## 4. Собрать GPU-образ

1. В GitHub откройте **Actions → Build GPU agent → Run workflow**.
2. Дождитесь успешной сборки `Dockerfile.gpu`. Она большая: устанавливает Torch, Musubi и модели окружения, **но не веса Krea/Klein/Wan**.
3. В GitHub Packages найдите `YOUR_REPOSITORY-gpu`. Сделайте package публичным для чтения YouGPU. Сам исходный репозиторий при необходимости может оставаться приватным. В образ не включаются ваши токены/датасеты.
4. Скопируйте точный путь образа. Для воспроизводимости используйте тег commit или digest, а не `latest`:

```text
ghcr.io/YOUR_LOGIN/YOUR_REPOSITORY-gpu:GITHUB_COMMIT_SHA
```

5. Добавьте этот путь в `AGENT_IMAGE` на Timeweb и обновите приложение.

Сборка фиксирует Musubi commit и согласованную пару Torch/Torchvision. Её успешность ещё не подтверждает работу CUDA на конкретном драйвере. Если shared GitHub runner исчерпал диск, используйте собственный builder с достаточным диском и тот же Dockerfile; не меняйте версии наугад.

## 5. Подключить YouGPU и веса

В студии → **Настройки**:

- YouGPU API key.
- Hugging Face read token.
- Civitai token, если нужен.

Сохранённые через UI токены шифруются в PostgreSQL с помощью SECRET_KEY и не возвращаются браузеру. Альтернатива — `YOUGPU_API_KEY`, `HF_TOKEN`, `CIVITAI_TOKEN` в окружении backend.

В **Модели и LoRA** выберите профиль → «Проверить доступ». Проверка разрешает gated-доступ, проверяет имена файлов и закрепляет HF revisions. Веса скачает GPU-агент, а не Timeweb. При 403 сначала примите условия модели; при 404 исправьте компонент. Пользовательский путь `{ "path": "/workspace/weights/model.safetensors" }` проверяется уже на GPU.

## 6. Подключить GPU вручную

Текущий режим — `COMPUTE_MODE=manual` (по умолчанию). Создание инстанса и завершение аренды выполняются в панели YouGPU. GPU-образ из шага 4 запускается на этом инстансе; Studio выдаёт одноразовый pairing code и точную команду Docker.

Полная инструкция с iPhone/Termius, требованиями к хосту, ресурсами для каждого пайплайна и завершением аренды: [MANUAL_GPU_RU.md](MANUAL_GPU_RU.md).

Каталог, аренда из UI, budget/idle auto-terminate и локальная оценка расхода больше не используются. YouGPU API key нужен только для необязательной проверки баланса; агент и задания работают без него. Одна задача использует одну GPU.

## 10. Обновление и backup

Сначала backup БД/S3. Push кода запускает новый web deploy; GPU jobs продолжаются по данным PostgreSQL и heartbeat. Сохраните SECRET_KEY. GPU-образ обновляется отдельно с новым тегом; уже запущенные узлы сохраняют прежний код до завершения задач.

Проверяйте восстановление backup на отдельной базе. Миграция старых материалов: ZIP датасета импортируется через редактор, LoRA — через upload, old state — только при совпадении trainer/model/dataset, иначе импортируйте как начальные веса вручную. Автоматический перенос всей истории прежней Studio не реализован.
