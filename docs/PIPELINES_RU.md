# Инструкции по пайплайнам

Рецепты закреплены за Musubi commit `f8a1b03794a49239a3539015075f5123d6c07d66`. Дата исследования — 27.10.2026. Параметры ниже — исходные ориентиры, а не результат обучения May в этой сборке. GPU qualification ещё требуется.

## Общее

1. Примите условия базовой модели, добавьте HF token.
2. В профиле проверьте компоненты. Успешная проверка заменяет main на точную ревизию и сохраняет размеры/файлы. Собственные пути относятся к GPU, а не Timeweb.
3. Выберите snapshot с английскими captions и правильным триггером.
4. Проведите короткий GPU smoke test, затем несколько сравнений checkpoint на фиксированных сценах. Проверяйте увеличенное лицо, анатомию, фигуру и управляемость prompt.
5. Не определяйте качество личности по одному loss и не зашивайте 1200 шагов для любых датасетов.

Веб-сервер не загружает Torch. Все GPU-зависимости находятся в отдельном образе. BF16-рецепты требуют совместимой GPU; наличие переключателя в UI не превращает две T4 в одну GPU 30 GB.

## Krea 2

**Обучение:** RAW DiT + Qwen-Image VAE + Qwen3-VL-4B-Instruct single safetensors. VAE preset использует проверенный файл `Comfy-Org/Krea-2/vae/qwen_image_vae.safetensors`, а не старую несуществующую ссылку Qwen-Image-Edit.

Исходный профиль: rank/alpha 32/32, LR 1e-4, AdamW8bit, batch 1, gradient checkpointing, SDPA, shift 2.5, weighting none. Для осторожного сравнения May можно вручную выбрать rank16/LR5e-5. Разрешение 1024 с buckets; уменьшение до 768 — отдельный эксперимент. Предпросмотр и state каждые 200 шагов, интервал настраивается.

При необходимости scaled FP8 включает оба обязательных флага тренера. Block swap задаётся явно, по умолчанию 0; он может существенно замедлять работу. Максимум Krea — 26 блоков, но это не рекомендация ставить максимум.

Встроенный sample — RAW с CFG. `--turbo_dit` намеренно не добавляется к block swap. После обучения экспортированная LoRA автоматически появляется в библиотеке: выберите её в Studio Krea Turbo и сравните новые сцены.

**Генерация Turbo:** 8 шагов, guidance1 в Musubi (CFG off), mu1.15, исходно 1024. Negative prompt не применяется. Несколько LoRA передаются с независимыми multiplier. Модель Krea в закреплённом тренере — T2I; обычное reference edit не обещается.

- https://github.com/kohya-ss/musubi-tuner/blob/f8a1b03794a49239a3539015075f5123d6c07d66/docs/krea2.md

## FLUX.2 Klein 9B

**Обучение:** Base9B, `model_version=klein-base-9b`; DiT, FLUX.2 AE и четыре shards Qwen3 8B encoder. Не используйте Diffusers transformer folder как single trainer file. Компоненты preset доступны для правки, файлы проверяются по HF API.

Исходно rank32, LR1e-4, AdamW8bit, BF16, gradient checkpointing, `flux2_shift`, weighting none. Rank16/LR5e-5 — предлагаемый дополнительный эксперимент, а не доказанная оптимальная настройка персонажа.

**Генерация Base:** 50 шагов, guidance4; поддерживается одно reference image через соответствующий control input. В закреплённом backend Base использует CFG и negative prompt. Не переносите это поведение на distilled. Уменьшать steps до 4 у Base без замены модели неверно.

Тренированная LoRA проверяется на Base. Генерация distilled и перенос адаптера на неё отложены до отдельного теста; это не автоматическая гарантия совместимости.

Источники:
- https://github.com/kohya-ss/musubi-tuner/blob/f8a1b03794a49239a3539015075f5123d6c07d66/docs/flux_2.md
- https://huggingface.co/black-forest-labs/FLUX.2-klein-base-9B

## Wan 2.2 A14B: LoRA

I2V и T2V — отдельные профили, high/low — отдельные эксперты. Нужны правильная пара DiT, UMT5-XXL и Wan2.1 VAE. VAE Wan5B не подходит.

В UI доступны low, high или два последовательных запуска. I2V cache запускается с `--i2v`. Диапазоны low/high: I2V0–900/900–1000, T2V0–875/875–1000, preserve_distribution_shape.

Предлагаемый осторожный эксперимент: rank16–32, LR5e-5–1e-4; в интерфейсе по умолчанию rank32/LR5e-5. Опубликованный пример тренера rank32/LR2e-4/shift3 не считается доказанным оптимумом May. Здесь training shift3; inference shift другой.

Начните с фото и коротких клипов 17/33 кадра, правильных captions и зафиксированных FPS. Число кадров — 4n+1. Сохранение внешности и обучение походке — разные задачи. Видеопроверка должна оценивать лицо во времени, дрейф, руки, переходы и движение камеры.

Полное состояние resume относится к конкретному эксперту. Возобновляйте экспертов отдельно. Внешнюю low-LoRA не загружайте автоматически в high. Поле expert у адаптера управляет назначением.

## Wan 2.2 A14B: генерация

I2V: выберите исходное фото, опишите действие/камеру, подключите совместимые I2V LoRA. T2V: опишите сцену и действие; нужны T2V компоненты.

Исходный тестовый профиль приложения: 832×480, 81 кадр, 16 FPS, 40 шагов, guidance5. Это наша отправная точка проверки, не универсальный рецепт качества. Flow shift: I2V5, T2V12. Настройки относятся к обычным checkpoints, не ускоряющим LightX2V/другим адаптерам.

High/low LoRA передаются в разные аргументы тренера. Галерея показывает готовый MP4 после подтверждённой загрузки. FPS экспорта не заменяет временной профиль генератора.

Источники Wan train/generate:

- https://github.com/Wan-Video/Wan2.2

## Wan 2.2 TI2V5B

Отдельная архитектура и отдельный VAE. Генерация через Diffusers, T2V и I2V. Исходно 1280×704 либо 704×1280, 121 кадр, 24 FPS, 50 шагов, guidance5, flow shift5. LoRA5B и обучение5B не включены.

Поле CPU offload здесь включает model CPU offload, а не блоки Musubi. Scaled FP8 в этом рецепте отклоняется. Не выдаём эти переключатели за одинаковые механизмы во всех моделях.

Источники:
- https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B-Diffusers
- https://huggingface.co/docs/diffusers/en/api/pipelines/wan

## Captions и клипы

Qwen2.5-VL формирует описания переменных свойств. Видео анализируется по 8 выборочным кадрам; автоматическая оценка person/face visibility и движение требуют ручной проверки. Лицо не идентифицируется автоматически как May.

FFmpeg ищет смены сцен, затем нарезает клипы внутри сцен. Можно выбирать длительность, overlap, FPS и извлечение отдельных кадров. Слишком короткая сцена может не дать клип выбранной длины. Все производные одного видео сохраняют общую группу.
