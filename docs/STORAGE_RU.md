# Рабочий диск GPU-агента

Docker named volume по умолчанию размещается в Docker data root, часто на системном диске 100 GB. Наличие большого /ephemeral само по себе не переносит туда /workspace. Именно это вызвало нехватку диска при переходе RAW → Turbo.

Новая команда в «Мощности → Получить код и инструкцию» использует bind mount /ephemeral/maymay-workspace:/workspace. Путь редактируется для другого провайдера. Перед запуском проверяются наличие /ephemeral как отдельного mountpoint (для стандартного пути), отсутствие уже созданного агента и минимум 150 GiB свободного места. Этот запас — начальное требование, не гарантия вместимости всех моделей. Команда не форматирует диски и не заменяет существующие контейнеры. При недостатке места модель выдаёт путь, свободный объём и объём недостающих файлов.

/ephemeral — временное хранилище. Завершение аренды может уничтожить его содержимое. Сохраняйте результаты и state во внешнем S3/скачивайте их. Для постоянного диска укажите его смонтированную папку. Системный Docker image остаётся в Docker data root; проверяйте свободное место и там.

## Уже работающий агент

1. Дождитесь окончания либо подтверждённой отмены заданий Studio. Не переносите данные во время записи результатов.
2. На GPU-хосте получите scripts/migrate_workspace.py из проверенной версии репозитория. Запустите `sudo python3 scripts/migrate_workspace.py` для проверки без изменений.
3. После проверки запустите `sudo python3 scripts/migrate_workspace.py --apply`.
4. Скрипт останавливает агент, копирует workspace, сохраняет текущий исправленный main.py, переименовывает старый контейнер и создаёт новый с прежними ENV и образом. Credentials и веса копируются. Старый том и контейнер не удаляются; при нестандартных mounts или существующей папке назначения скрипт отказывается менять данные.
5. Проверьте `sudo docker exec maymay-agent df -h /workspace`, `sudo docker logs --tail 80 maymay-agent` и heartbeat в Studio. Не запускайте старый и новый агент одновременно. Для отката остановите новый контейнер и используйте сохранённый старый. Очистку резервной копии выполняйте только после проверки внешних результатов.

Перенос сохраняет старую версию образа. Новые caption-модели требуют отдельного обновления GPU-образа после завершения задач. CPU-тесты не подтверждают миграцию на реальном Docker/GPU.
